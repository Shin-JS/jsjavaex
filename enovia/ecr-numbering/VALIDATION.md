# 검증 결과

2026-10-20, OpenJDK 17에서 `--release 8`로 전체 Java 소스와 테스트를 컴파일했습니다. SDK는 tests/stubs의 대역을 사용했습니다.

결과: **143,961 assertions 통과**, 유효한 순번 **35,973개 전수 검사**.

- 전체 순번의 유일성, 길이, 정수↔표시 순번 왕복 변환, A000 제외.
- 9999/A001, A999/B001, Z001/Z999와 범위 초과.
- 5개 사업부와 15자리 name.
- 잘못된 사업부·날짜 범위·순번, 기본 Locale이 바뀐 경우 ASCII 숫자 유지.
- UTC 날짜와 한국 날짜가 다른 시점의 한국 기준 채번.
- 대역을 통한 잠금→조회→갱신 호출 순서, 다음 정수 저장.
- 사업부·날짜별 카운터 분리, 매핑 누락·동일 카운터 재사용·잘못된 날짜 거부.
- update 트랜잭션 없음, 읽기 트랜잭션, 잘못된 카운터 값, 저장 실패 처리.

**미검증:** 실제 ENOVIA SDK JAR와의 컴파일, 설치된 생성 메서드의 호출 연결, 실제 카운터의 자료형·권한·트리거, 다중 WAS DB 잠금, 롤백, 검색/분류 저장과 응답 처리.

대역은 DB 잠금이나 롤백을 구현하지 않습니다. 대역 검사 통과를 실제 동시성·트랜잭션 통합 검증으로 해석하지 않습니다. 배포 환경 확인 항목은 INTEGRATION.md에 있습니다.
