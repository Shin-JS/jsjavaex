# 검사 결과와 설치 환경 확인 범위

## 통과한 검사

- 네 JS 변경 조각의 JavaScript 문법 검사.
- 공개 R2024x 원본의 해당 AMD factory에 모든 추가 함수와 호출을 삽입한 뒤 문법 검사. 원본 전체 파일은 이 저장소에 올리지 않았습니다.
- 대역 검사: 위젯/타입 제한, 대화상자별 분리, 고정 클래스 설정, 검색 UI 없는 폼 구성.
- 대역 검사: 컨트롤러 준비 후 조회, 선택과 속성 준비 완료 구분, 준비 전 생성 거부, 빈 속성 배열 완료.
- 대역 검사: blur·속성 검증 실패, 문맥 변경 후 생성 거부, 폼 부모/순서 복원, 늦은 응답 무시.
- 대역 검사: 고정 클래스 ID 누락, 잘못된 클래스 타입, 라이브러리 경로 불일치, 속성 응답 오류, 타임아웃.

대역 검사 재실행:

```sh
node tests/test-auto-fields.cjs
```

## 설치 환경 확인

실제 생성 유형 이름과 클래스 physicalid는 아직 제공받지 않았습니다. 실제 값을 설정한 뒤 확인해야 합니다.

- 실제 AMD 모듈 위치와 수정 파일의 브라우저 로딩.
- 생성 화면의 SecurityContext와 지정 유형 조회.
- getClassPaths의 경로·타입, 라이브러리 경로 확인.
- select/change의 모델 생성과 실제 속성 로딩, 폼 반영 뒤 완료 통지.
- 입력값 커밋·필수값·범위 검사, Enter/버튼/반복 생성.
- 클래스 연결과 속성값 영구 저장, 저장 실패 전파.
- 다른 위젯에서 원래 라이브러리 선택과 생성 유지.

대역 검사는 실제 WUX/tweaker, 서버 API, 동시 대화상자, 저장의 통합 검증을 대신하지 않습니다. OOTB 내부의 공용 provider·이벤트 상태까지 이번 변경이 전부 분리하는 것은 아닙니다.

## 지정 클래스 + 유형 고정 변경

- 대역 검사: 부서/조직 파싱 없이 지정한 classId 사용, 클래스 ID 누락/잘못된 표시 모드 거부.
- 대역 검사: 숨김/읽기 전용 유형, 단일 선택지와 NLS 유지, 원래 persistData 정의 유지.
- 대역 검사: 다른 유형의 속성 정의로 값만 덮어쓰는 것을 거부, 제출 시 실제 유형 불일치 거부.
- 대역 검사: CreateNew 초기 옵션의 type/typeName/preferedType 일치, 비활성 위젯 옵션 유지.
- 설치 환경의 실제 비활성 표시 모양과 지정 subtype의 서버 생성 지원은 별도 확인이 필요합니다.
- 기존 조직 파싱/조직별 매핑 검사는 과거 방식의 결과입니다. 현재 실행 방식은 고정 클래스입니다.
- 커스터마이징 없는 서버에서도 발생한 ClassificationAttributeUtil.java:95 오류는 이번 변경에서 해결/검증하지 않았습니다.

- 참조 ENONewAttributeUtil을 대역 Attribute 모델로 실행해 isReadOnly→readOnly 변환, 고정값 유지, visible:false 유형 제외를 확인했습니다. 실제 WUX 렌더링 검증은 아닙니다.
