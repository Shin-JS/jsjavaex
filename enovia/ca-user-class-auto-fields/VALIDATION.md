# AMD 분리 검사 결과와 현장 확인 범위

## 이번 분리에서 통과한 검사

- 기존 추가 함수 17개의 본문을 이동 전 코드와 대조하여 동일함을 확인했습니다. AMD 래퍼/공개 메서드와 배치만 변경했습니다.
- 실제 커스텀 define을 대역 AMD 로더로 실행하여 모듈 ID, 지역 require 의존성, 공개 메서드 반환, 전역 함수 미노출을 검사했습니다.
- AMD 파일 로딩만으로 세션·타이머를 만들지 않으며, 세션/선택 모델은 대화상자별로 생성되는 것을 검사했습니다.
- 전역 require를 제거한 대역에서도 factory의 지역 require로 AttributesUtils를 지연 로드하는 것을 확인했습니다.
- 7개 OOTB 모듈의 의존성/인자 대응을 검사했습니다. 기존 순서/인자는 유지하며 커스텀 모듈과 인자는 항상 마지막입니다. CSS 의존성 자리를 채우는 두 모듈도 검사했습니다.
- 배포 변경 메모의 실제 헤더와 테스트 fixture를 대조했습니다.
- 공개 R2024x 원본의 7개 define 헤더와 본문에 연결 호출을 삽입한 뒤 JavaScript 문법 검사를 통과했습니다. OOTB 원본 전체 파일은 이 저장소에 올리지 않았습니다.

## 유지된 대역 회귀 검사

- 위젯/타입 적용 제한, 대화상자별 세션 분리, 부서 조회 없는 고정 클래스 적용.
- 컨트롤러 준비와 클래스 선택/속성 로딩 완료 구분, 준비 전 생성 거부, 빈 속성 배열 정상 완료.
- 속성 필드/값 객체 유지, blur·속성 검증 실패, 현재 유형 불일치, 문맥 변경 후 생성 거부.
- 폼의 원래 부모/순서 복원, 종료 후 늦은 응답 무시.
- 클래스 ID 누락, 잘못된 클래스 타입, 라이브러리 경로 불일치, 응답 오류, 타임아웃.
- 유형 숨김/읽기 전용, 단일 선택지와 NLS/원래 persistData 유지, CreateNew 초기 타입 옵션 일치.

폴더에서 재실행:

```sh
node tests/test-auto-fields.cjs
node tests/test-amd-headers.cjs
```

amd-headers.json은 참조 R2024x의 헤더와 변경 헤더만 저장한 fixture입니다. 서버/WUX 구현을 포함하지 않습니다. 설치 버전 헤더와 같다는 보증 자료는 아닙니다.

## 현장에서 아직 확인하지 못한 부분

- DS/ZCAAutoClass/ZCAAutoClass가 실제 새 파일 URL로 해석되는지, 브라우저가 갱신된 OOTB 파일을 실행하는지.
- 현재 설치 버전의 의존성/인자 개수 및 CSS 자리 인자 대응.
- OOTB 모델 push 뒤 tagClassModel 호출과 실제 폼 반영 뒤 notifyAttributesLoaded 호출의 진입.
- 준비 메시지에 머무르는 현재 현장 문제의 원인과 해결.
- 실제 WUX의 유형 비활성 모양, 입력값 커밋·필수값·범위 검증.
- Enter/버튼/반복 생성, 새 CA의 분류 연결과 속성값 저장, 동시 대화상자, 다른 위젯의 기존 동작.

커스터마이징 없는 서버에서도 재현된 ClassificationAttributeUtil.java:95 오류는 별도로 보류 중입니다. 이번 AMD 분리가 해당 저장 오류를 해결한 것은 아닙니다. OOTB 내부 공용 provider와 이벤트 상태까지 모두 분리한 것도 아닙니다.
